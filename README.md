# Project DD

用于 Codex 和 Claude Code 的公开信息尽调 Skill。输入公司名、官网或企业编号，即可获得一份带来源的四栏简报，用于接洽前了解公司背景、监管与声誉风险，以及与 United Stables（U）的业务关联。

## 安装

打开 Codex 或 Claude Code，把下面这句话直接发给它。

```text
请帮我安装这个链接里的 Project DD Skill。
https://github.com/jonas-c123/project-dd/tree/main/project-dd
```

## 使用

在 Codex 输入：

```text
$project-dd 帮我对 Predict.fun 做公开尽调
```

在 Claude Code 输入：

```text
/project-dd 帮我对 Predict.fun 做公开尽调
```

同名公司较多时，可以一起提供官网、注册地或登记号。

## 调查流程

| 顺序 | 怎么查 | 查完得到什么 | 注意事项 |
| --- | --- | --- | --- |
| 1. 确认主体 | 用法定名称和登记号核对官方记录，再用站外资料核对官网 | 法定主体、登记状态和官网归属 | 品牌、母公司和地区子公司分别识别 |
| 2. 查公司背景 | 看登记、集团披露、客户公告和公开案例，按主营业务整理 | 公司简介、主营业务和可核实的集团关系 | 集团数据与单个公司数据分开 |
| 3. 查监管与声誉 | 按主体、活动和地区核对牌照、处罚、制裁和公开诉讼 | 有出处的关键发现及待核实事项 | 区分被处罚的主体、决定类型和案件阶段 |
| 4. 评估与 U 的关联 | 从有证据的业务找合作切入点，再把影响判断的缺口转为客户问题 | 潜在机会和需要向客户确认的问题 | 区分已上线业务与待讨论的合作方向 |

## 报告包含什么

- **Company Overview**：公司基本信息、主营业务和集团背景。
- **Key Findings / Red Flags**：先给主要结论，再附公开证据。
- **Potential Opportunities**：有公开业务依据的潜在合作方向。
- **Questions for Client**：会影响初筛判断、需要客户补充的问题。

报告默认直接在对话中交付。查过无结果或该项不适用时写 `NA`。关键记录无法查询时标记待核实，并尽可能提供官方查询入口。交付前逐条打开证据链接，核对内容和主体。

范围限于公开信息初筛。正式 KYB、资金来源、钱包信息、预计铸币量和准入留到后续流程。
